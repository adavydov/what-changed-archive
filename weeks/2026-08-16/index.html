Плагины агентов и проверка большой переделки кода

Три основных вывода

  1. Agent Plugins 1.0 сокращает повторную упаковку одних и тех же навыков и MCP-интеграций для нескольких клиентов. Поддерживаемое содержимое обнаруживается из общего пакета.
  2. Специальные расширения клиента остаются в собственном каталоге. Организация управляет доступными плагинами и маркетплейсами, а правила MCP отдельно ограничивают подключаемые серверы.
  3. В описанной переделке кода спецификацию сначала сверяют с существующей системой, затем реализацию — с зафиксированным документом. Проверка соответствия спецификации продолжала находить отклонения после исправления ошибок компиляции, типов и модульных тестов.

GitHub объявляет поддержку Agent Plugins 1.0: навыки и конфигурации инструментов можно распространять одним пакетом между совместимыми клиентами. Общий формат охватывает переносимую часть, а специальные возможности Copilot сохраняются в отдельном каталоге. Корпоративная установка продолжает подчиняться существующим правилам организации.

В другом материале разработчик AICode описывает большую архитектурную переделку с агентом. Сначала он многократно уточняет спецификацию относительно кода, затем фиксирует её и проверяет реализацию. Свежие сессии возвращаются к одному описанию цели, а человек управляет переходом между этапами.

Agent Plugins 1.0: один пакет навыков и инструментов для нескольких агентов

GitHub описывает поддержку открытого стандарта Agent Plugins 1.0 в VS Code, Copilot CLI, Copilot SDK и приложении Copilot. Статья разбирает устройство переносимого пакета, сохранение возможностей конкретного клиента и корпоративное управление установкой.

  • Навык и конфигурацию MCP-сервера теперь можно упаковать один раз для совместимых агентных клиентов; раньше одинаковое содержимое приходилось сопровождать в разных манифестах и структурах каталогов.
  • Общая часть плагина переносится между клиентами, а дополнительные возможности Copilot сохраняются в отдельном каталоге. Старые плагины продолжают работать без обязательной миграции.
  • Корпоративное распространение использует существующие managed settings: разрешение плагинов, выбор маркетплейсов и отдельные правила доступа к MCP-серверам.

Как удержать цель большой переделки

Автор / участники: Joël Abenhaïm

Большая переделка кода через уточнение и фиксацию спецификации

Разработчик AI Sovereign Labs описывает архитектурную переделку собственного coding-агента AICode на TypeScript. Новое поведение нужно было вывести из пользовательской задачи, а затем согласованно провести через сотни связанных файлов. В редакции статьи от 15 августа он разбирает процесс, в котором человек управлял этапами, а написанный агентом код не просматривал построчно.

  • Проверка идёт в двух направлениях: сначала спецификацию многократно сверяют с существующим кодом, затем реализацию — с зафиксированной спецификацией. Это удерживает цель большой переделки между свежими сессиями агента.
  • За 14 проходов уточнения найдено около 85 проблем в спецификации, за 17 проходов проверки — 116 отклонений в коде. Даже пятнадцатая проверка реализации дала ещё десять исправлений.
  • По отчёту автора, изменение 189 файлов заняло три дня и $2430 на инференс. Новое поведение работало при первом ручном запуске и примерно в 30 последующих сессиях; исходный код проекта закрыт.
