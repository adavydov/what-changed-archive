Jay Parikh: общий контекст и контроль расходов в следующем GitHub

Сразу после выступления на GitHub Universe Джей Парик обсуждает со swyx, как платформа меняется под рост людей и coding-агентов. Разговор проходит от инфраструктурного масштаба и настраиваемых рабочих процессов к общему harness, переносимому контексту, защите и связи расходов на токены с результатом команды.

Основные мысли

  • GitHub хочет сохранять контекст, память и предпочтения между телефоном, desktop, VS Code и вебом через общий harness, при этом оставляя выбор моделей.
  • Парик предлагает сохранять настраиваемые примитивы для разных способов работы: агентный поток может обходиться без привычного pull request, тогда как крупной компании он по-прежнему нужен.
  • Контроль токенов должен соединять выбор модели, рекомендации по стоимости и ограничения компании с измеримыми эффектами: выпуском функций, экономией, удержанием или CSAT.

Платформа меняется под новый объём работы

Парик называет 225 млн разработчиков на GitHub и второй год подряд, когда в среднем каждую секунду приходит ещё один. В отчёте Octoverse приведены 17,9 млрд push, 34,3 млрд commit и 1,3 млрд pull request. Во вступлении swyx отдельно подчёркивает рост агентной активности и нагрузку, которую он создаёт на хранилища, метаданные и остальную инфраструктуру.

GitHub становится доступен и тем, кто раньше не считал себя квалифицированным программистом. Парик приводит журналиста, который с агентом создал repo и захотел поделиться им ради обратной связи. Для него GitHub остаётся сообществом: AI помогает большему числу людей создавать вещи вместе.

Рабочий процесс можно собирать из примитивов

swyx спрашивает о предложении Питера Штайнбергера отказаться от привычного pull request. Парик отвечает через разнообразие пользователей: большая компания, студент и экспериментальный личный проект требуют разных правил. У него самого есть repo, куда он сразу отправляет идеи, не заводя issues и PR. Платформа должна позволять конфигурировать эти понятия и собирать нужный процесс.

Точно так же расширяется содержимое repo: рядом с исполняемым кодом появляется markdown с инструкциями и контекстом. При этом огромный объём старых Java и .NET-систем продолжает требовать исправлений, модернизации и оптимизации. Платформе приходится поддерживать оба мира.

Harness, Fusion и накопление контекста

Copilot harness можно использовать через SDK для собственных приложений. Его принципы включают работу с несколькими моделями и постоянную адаптацию к инструментам, MCP и новым возможностям. Fusion должен разбирать будущую единицу законченной программной работы и выбирать подходящую модель по качеству, скорости и цене, снимая эту нагрузку с инженера.

Общий harness связывает Copilot-приложение, VS Code и веб. Идею можно отправить с телефона и продолжить на компьютере; repo, issues, PR, замечания безопасности, память и предпочтения должны оставаться общими. Парик видит продуктовую ценность в том, что опыт работы на разных поверхностях накапливается в одном месте, хотя модели и инструменты внутри можно менять.

Безопасность и цена самостоятельной замены зависимостей

Рост генерации кода требует сохранять планку качества. Парик перечисляет Code Review Max, более глубокое AI-сканирование и блокировку случайно отправленного секрета ещё до попадания в repo. Команды GitHub и Microsoft также работают с maintainers и package managers, включая задержку новых пакетов и снятие с публикации скомпрометированных проектов.

swyx предлагает возможную реакцию на дешёвый код: отказаться от тысяч внешних зависимостей и переписать нужное самостоятельно. Парик признаёт, что вопрос возникает у клиентов, но напоминает о перемещении обязанности: если из двух тысяч проектов оставить двадцать, остальные 1980 теперь надо поддерживать самому. Он предпочитает улучшать безопасность общей open-source основы.

Что ждать через год

Завершение переезда на Azure Парик называет целью следующего года. Рост масштаба требует заметных улучшений на каждом инфраструктурном слое. При этом он не берётся предсказать, будут ли команды управлять десятками, сотнями или тысячами агентов, и возвращается к гибким общим примитивам.

Отдельной темой становятся токены: компаниям нужны детализация затрат, рекомендации о смене модели и ограничения для крупных организаций. Разговор об окупаемости не сводится к прямой выручке программиста. После замечания swyx Парик перечисляет экономию, вовлечённость, удержание и CSAT — результаты, с которыми могут связываться продуктовые и инженерные команды.

В конце собеседники обсуждают бейдж GitHub Universe в форме маленькой игровой приставки, созданный с Copilot. Для swyx это пример того, как модели снижают порог эксперимента на стыке программ и аппаратуры.
