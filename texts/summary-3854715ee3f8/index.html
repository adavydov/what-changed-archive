Cloudflare и Deno: открытый runtime ещё должен стать пригодной для переноса платформой

Райан Даль и Кентон Варда объясняют объединение Deno и Cloudflare через задачу самостоятельного запуска приложений. Открытого runtime оказалось недостаточно: к нему нужны состояние, маршрутизация и операционное устройство, которые обычная команда сможет поддерживать за пределами Cloudflare.

Основные мысли

  • Durable Objects соединяют адресуемое состояние, SQLite и однопоточное исполнение в общей модели приложения.
  • Открытый workerd помог продавать платформу, но не дал готовой масштабируемой системы self-hosting.
  • celld должен дополнить runtime более простым операционным устройством с object storage.

Общая модель приложения

Deno присоединяется к Cloudflare для объединения celld и workerd. Ryan Dahl описывает переход от улучшения JavaScript runtime к более крупной задаче: вычисления, состояние, хранилище, коммуникации и масштабирование как общая модель приложения.

Durable Object — адресуемый объект с собственным SQLite и однопоточным исполнением. Если в чате выделить объект каждому каналу, это сразу задаёт шардирование состояния и WebSocket-связей. На такой основе можно строить очереди, KV и durable execution.

celld проектировался для самостоятельного запуска: Rust binary, множество экземпляров и единственное внешнее сервисное хранилище — object storage. Цель — не собирать отдельный инфраструктурный проект под каждую часть приложения.

Почему открытого кода оказалось мало

Varda утверждает, что крупные клиенты, включая Shopify в обсуждении 2022 года, не согласились бы на Workers for Platforms без открытого runtime. Поэтому workerd открыл тот же код, который используется в production, а не похожую альтернативу. По его словам, часть клиентов уже ушла с этим кодом, и возможность ухода помогла привлечь других.

При этом Cloudflare признаёт слабость собственной реализации self-hosting: runtime открыт, но соседние инструменты и сервисы не возникли сами. Durable Objects в публичном workerd работали только внутри одного экземпляра, пригодного для локальной проверки, а не масштабируемого production.

Внутренняя маршрутизация Cloudflare зависела от большого набора сервисов и SRE-команды; она не подходила обычному self-hoster. Задача была известна с первого выпуска, но команда не довела её до результата, включая неудачную попытку прошлой весной.

Что должно дать объединение

celld оказался совместимой реализацией с другим операционным устройством. После объединения команды планируют сделать самостоятельный запуск полноправным способом использования. Слияние кода и дальнейшие объявления ещё впереди.

Варда связывает возможность ухода с доверием к новому программному интерфейсу: клиенту легче принять платформу, когда он может продолжить работу отдельно от поставщика. В статье этот аргумент соседствует с признанием конкретного пробела production self-hosting.
