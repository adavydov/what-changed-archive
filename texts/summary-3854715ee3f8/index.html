Cloudflare и Deno: открытый runtime ещё должен стать пригодной для переноса платформой

Три основных вывода

  1. Varda утверждает, что крупные клиенты, включая Shopify в обсуждении 2022 года, не согласились бы на Workers for Platforms без открытого runtime. Поэтому workerd открыл тот же код, который используется в production, а не похожую альтернативу. По его словам, часть клиентов уже ушла с этим кодом, и возможность ухода помогла привлечь других.
  2. При этом Cloudflare признаёт слабость собственной реализации self-hosting: runtime открыт, но соседние инструменты и сервисы не возникли сами. Durable Objects в публичном workerd работали только внутри одного экземпляра, пригодного для локальной проверки, а не масштабируемого production.
  3. Экономический аргумент автора состоит в том, что право ухода помогает продаже нового программного интерфейса. Его заявления о более низкой цене и превосходстве Workers остаются утверждениями заинтересованного поставщика; статья полезна прежде всего признанием конкретного production-пробела.

Оригинал

Кто говорит: Ryan Dahl и Kenton Varda

Главная мысль: Для внедрения нового программного интерфейса возможность уйти может быть условием покупки; открытая лицензия сама по себе не создаёт масштабируемый и поддерживаемый путь ухода.

  • Deno присоединяется к Cloudflare для объединения celld и workerd. Ryan Dahl описывает переход от улучшения JavaScript runtime к более крупной задаче: вычисления, состояние, хранилище, коммуникации и масштабирование как общая модель приложения.
  • Durable Object — адресуемый объект с собственным SQLite и однопоточным исполнением; разделение чата по объекту на канал сразу задаёт шардирование состояния и WebSocket-связей. На такой основе можно строить очереди, KV и durable execution. Это описание программной модели, не независимый benchmark её экономичности.
  • celld проектировался для самостоятельного запуска: Rust binary, множество экземпляров и единственное внешнее сервисное хранилище — object storage. Цель — не собирать отдельный инфраструктурный проект под каждую часть приложения.
  • Varda утверждает, что крупные клиенты, включая Shopify в обсуждении 2022 года, не согласились бы на Workers for Platforms без открытого runtime. Поэтому workerd открыл тот же код, который используется в production, а не похожую альтернативу. По его словам, часть клиентов уже ушла с этим кодом, и возможность ухода помогла привлечь других.
  • При этом Cloudflare признаёт слабость собственной реализации self-hosting: runtime открыт, но соседние инструменты и сервисы не возникли сами. Durable Objects в публичном workerd работали только внутри одного экземпляра, пригодного для локальной проверки, а не масштабируемого production.
  • Внутренняя маршрутизация Cloudflare зависела от большого набора сервисов и SRE-команды; она не подходила обычному self-hoster. Задача была известна с первого выпуска, но команда не довела её до результата, включая неудачную попытку прошлой весной.
  • celld оказался нужной совместимой реализацией с другим операционным устройством. План после объединения — сделать самостоятельный запуск первым классом поддержки, слияние кода и дальнейшие объявления ещё впереди. Это не доказательство, что весь будущий перенос уже работает.
  • Экономический аргумент автора состоит в том, что право ухода помогает продаже нового программного интерфейса. Его заявления о более низкой цене и превосходстве Workers остаются утверждениями заинтересованного поставщика; статья полезна прежде всего признанием конкретного production-пробела.
