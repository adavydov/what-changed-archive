Sparqlite: что делать после двенадцати часов автономной разработки

Саймон Уиллисон поручил Claude Code Ultracode создать расширение SQLite на Rust для SPARQL. Более чем двенадцатичасовая автономная сборка привела его к отдельному вопросу: как разобраться в большом созданном проекте и понять, зачем он нужен.

Основные мысли

  • Ultracode самостоятельно строил и координировал сеть подагентов более двенадцати часов.
  • После генерации понадобились README для каждого crate, учебник и пример базы.
  • Освоение большого результата требует собственного времени и ясно выбранной потребности.

Автономная сборка

Уиллисон попросил расширение SQLite на Rust для SPARQL. Случайное слово delete в начальном запросе оказалось опечаткой, которую он отдельно поясняет. В режиме Ultracode система сама выстроила и координировала сеть подагентов и работала более двенадцати часов.

По аннотации проекта, расширение хранит графовые данные в виде RDF-квадов в обычных таблицах SQLite. Запросы и обновления SPARQL 1.1 выполняются непосредственно внутри процесса SQLite, без перевода в SQL.

Работа после генерации

На следующий день автор запросил README для каждого crate, учебник установки и SPARQL и пример базы. Чтобы пользоваться результатом, ему понадобился новый слой объяснений.

Во вступлении Уиллисон пересказывает функциональность и тесты проекта, но сам ещё не смог обозреть весь код. Даже изучение документации требует существенной работы. Отсюда его сомнение в ценности системы, которую создали без ясно выбранной потребности.
