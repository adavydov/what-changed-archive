Agent Plugins 1.0: один пакет навыков и инструментов для нескольких агентов

GitHub описывает поддержку открытого стандарта Agent Plugins 1.0 в VS Code, Copilot CLI, Copilot SDK и приложении Copilot. Статья разбирает устройство переносимого пакета, сохранение возможностей конкретного клиента и корпоративное управление установкой.

Основные мысли

  • Навык и конфигурацию MCP-сервера теперь можно упаковать один раз для совместимых агентных клиентов; раньше одинаковое содержимое приходилось сопровождать в разных манифестах и структурах каталогов.
  • Общая часть плагина переносится между клиентами, а дополнительные возможности Copilot сохраняются в отдельном каталоге. Старые плагины продолжают работать без обязательной миграции.
  • Корпоративное распространение использует существующие managed settings: разрешение плагинов, выбор маркетплейсов и отдельные правила доступа к MCP-серверам.

Что именно становится переносимым

Agent Plugins 1.0 объединяет agent skills и настройки MCP-серверов в один устанавливаемый пакет. Например, плагин может содержать инструкцию по развёртыванию приложения и интеграцию с инструментом, который это развёртывание выполняет. До появления общего формата разработчик уже мог предлагать такой плагин для нескольких агентов, но для каждого клиента требовались собственный манифест и расположение файлов. Навык и сервер оставались одинаковыми, а их упаковку приходилось дублировать.

Стандарт был опубликован 6 августа совместно с AWS, Anysphere, Microsoft, OpenAI и Vercel; в тот же день Google присоединилась к основным сопровождающим. GitHub подчёркивает независимое от отдельного поставщика управление стандартом. В сообщении от 12 августа компания объявляет общедоступную поддержку в VS Code, Copilot CLI, Copilot SDK и приложении Copilot на всех тарифах Copilot. Совместимый клиент обнаруживает в общем пакете те навыки и конфигурации MCP, которые умеет использовать.

Как устроен общий пакет

Переход на спецификацию в основном касается манифеста: в plugin.json добавляется ссылка $schema, навыки остаются в каталоге skills/, а конфигурация MCP помещается в mcp.json. Специфические для Copilot файлы переносятся в com.github.copilot/. Другие клиенты игнорируют этот каталог, поэтому общая часть пакета сохраняет переносимость.

В каталоге Copilot продолжают жить пользовательские агенты, команды, правила и hooks, которые загружаются в VS Code, CLI и приложении. CLI и приложение также могут использовать дополнительные расширения, например canvases. Так разработчик поддерживает общий пакет и сохраняет специальные возможности своего основного клиента. Уже существующие плагины Copilot без Agent Plugins 1.0 остаются поддерживаемыми: принудительно переделывать их не требуется.

Установка и корпоративные правила

В VS Code, Copilot CLI и приложении по умолчанию доступен маркетплейс Awesome Copilot, откуда можно устанавливать плагины нового формата. Для организаций переносимость пакетов сопровождается общим способом управления: клиенты Copilot Business и Enterprise используют существующие managed settings в VS Code, CLI, приложении и облачном агенте.

В managed-settings.json параметр enabledPlugins позволяет автоматически устанавливать или блокировать конкретные плагины; extraKnownMarketplaces добавляет доступные источники; strictKnownMarketplaces ограничивает установку управляемыми маркетплейсами. Настройки предприятия задают базовый набор, а одобренные настройки отдельных команд дополняют его. Уже действующие правила для плагинов распространяются и на Agent Plugins 1.0, поэтому отдельная политика для нового формата не нужна.

Доступ к инструментам контролируется отдельно

Плагин может приносить с собой конфигурацию MCP-сервера. GitHub предлагает сочетать управление пакетами с MCP allowlists: отдельный сервер можно разрешить или заблокировать по URL, команде запуска или имени. Организация получает контроль и над тем, какие пакеты доступны разработчикам, и над инструментами, которые эти пакеты подключают.
