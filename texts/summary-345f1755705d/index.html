Саймон Уиллисон: сервис должен уметь остановиться на лимите расходов

Саймон Уиллисон рассматривает неожиданные счета как препятствие для личных AI-проектов. Агенту легко создать код с платными API, поэтому контроль бюджета должен работать и в отсутствие человека.

Основные мысли

  • Письмо о достижении бюджета не останавливает работающий код и последующие расходы.
  • Уиллисон предлагает жёсткий предел по умолчанию с явным решением пользователя снять его.
  • Наличие ограничения может стать критерием, по которому агент выбирает провайдера для новичка.

Ограничение, которое исполняет инфраструктура

Агенты снижают трудность запуска полезного приложения, но оно продолжает вызывать платные API, расширять хранилище и потреблять вычисления. Ночное уведомление не мешает ему потратить ещё деньги. Уиллисон предлагает возвращать ошибку после установленной суммы, оставляя возможность осознанно снять ограничение.

Он понимает, почему бизнес опасается остановки приложения, но ожидает, что многие создатели личных проектов предпочтут её неожиданному счёту на десятки тысяч долларов. Страх неконтролируемого AWS-счёта сам по себе мешает людям начинать.

Как выбирать сервисы для агентного кода

Уиллисон ссылается на объявленную в сентябре функцию AWS spend limit и июльские Google Cloud Spend Caps. Для AWS он отмечает ограниченную доступность новой среды: существующие аккаунты требуют отдельного внимания к условиям.

В дальнейшем сами агенты могли бы выбирать провайдеров с жёсткими лимитами и предупреждать неопытного пользователя о сервисах без них. Так бюджетная граница сохраняется даже тогда, когда человек недоступен.
