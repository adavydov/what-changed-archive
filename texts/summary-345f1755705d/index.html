Саймон Уиллисон: агентам и облачным сервисам нужны жёсткие лимиты расходов

Разработчик Саймон Уиллисон разбирает простую продуктовую защиту для мира, где агенты легко запускают платные API и облачные приложения: месячный бюджет должен автоматически останавливать потребление.

Основные мысли

  • Уиллисон предлагает по умолчанию останавливать платные сервисы при достижении бюджета, поскольку письмо не прекращает расходы.
  • Снять ограничение пользователь сможет явным выбором с согласием оплатить дальнейшее потребление.
  • В статье сопоставлены новые лимиты AWS с ещё ограниченным развёртыванием и Google Cloud Spend Caps для отдельных сервисов проекта.

Почему уведомления недостаточно

Coding agents и их более доступные пользователю версии уменьшают усилия, необходимые для запуска полезного кода. Но этот код может вызывать платные API, использовать хостинг, увеличивать хранение данных и вычисления. Уиллисон предлагает сделать жёсткий месячный бюджет обычным свойством таких сервисов: после заданной суммы потребление прекращается, а приложение получает ошибки.

Письмо о превышении бюджета оставляет счётчик включённым. Если уведомление приходит ночью, к утру ошибка в приложении успевает добавить сотни или тысячи долларов расходов. Уиллисон понимает возражение о доступности рабочего сервиса, но предполагает, что большинство компаний и частных пользователей предпочли бы сбой неожиданному счёту в десятки тысяч долларов.

Как дать пользователю контроль

Ограничение, по его предложению, должно действовать по умолчанию. Желающий непрерывной работы сможет убрать его отдельным понятным переключателем и явно принять ответственность за дальнейший счёт. Так решение о финансовом риске принимается до запуска.

В первую очередь Уиллисон хотел увидеть такую функцию у AWS: страх неуправляемого счёта, по его наблюдениям, удерживает людей от личных проектов в этом облаке. Во время подготовки статьи он обнаружил анонс AWS от 16 сентября: при переходе проекта на платный план можно установить месячный предел, после которого проект приостанавливается до следующего месяца. Документация при этом сообщает об ограниченном числе пользователей, получающих новый интерфейс; автор ждёт его более широкого распространения, в том числе для существующих аккаунтов.

Что уже появляется у облаков и чего автор ждёт от агентов

Google Cloud в июле представил Spend Caps, позволяющие установить месячный финансовый потолок для определённых сервисов внутри проекта. Уиллисон воспринимает эти запуски как начало нужной тенденции.

В идеале сами агенты помогали бы пользователям выбирать поставщиков с жёсткими ограничениями и предупреждали неопытных разработчиков, когда развёртывание приложения оставляет расходы без верхней границы.
