Datasette Lite: воспроизводимое серверное приложение помещается в ссылку

Саймон Уиллисон, создатель Datasette, переписал её браузерную версию. Он объясняет, как запускать обычное Python-приложение с базой SQLite и JavaScript-плагинами прямо у читателя, а ссылкой передавать точную конфигурацию демонстрации или воспроизведения ошибки.

Datasette Lite запускает Python через Pyodide и WebAssembly в браузере. Из URL можно загрузить SQLite, JSON, CSV или SQL-скрипт; выбрать опубликованную версию Datasette либо конкретный commit, tag или branch; поставить плагины из PyPI или wheel-файлов; выбрать версию SQLite. В примере ссылка открывает базу стран и столиц вместе с картографическим плагином и настройками отображения.

Смысл такой адресуемости — дать человеку именно тот экземпляр программы, о котором идёт речь. Уиллисон показывает один и тот же pagination-баг на Datasette 1.0a42 и исправление на 1.0a43 двумя ссылками. Для демонстрации функции или ошибки не нужно отдельно поднимать полноценный сервер. Файлы данных по URL должны отдавать открытые CORS-заголовки; для примеров он использует Gists.

Первоначальная Datasette Lite появилась ещё в 2022 году. Тогда Python работал в web worker, а результат запроса вставлялся в верхнюю страницу через innerHTML. Для базового приложения это подходило, но вставленные таким способом script-теги не выполнялись, а дополнительные CSS и JavaScript не загружались как в обычном приложении. Поэтому плагины и другие интерактивные функции ломались.

Новая версия перехватывает обычные HTTP-запросы через service worker: браузер запрашивает страницу, скрипт или CSS по привычному адресу, а ответ приходит от клиентского Python. Вложенный iframe затем отображает полученный результат как обычную страницу.

Один service worker обслуживает все вкладки домена. Если направить всё в один экземпляр Datasette, разные ссылки с разными плагинами будут мешать друг другу. Поэтому каждая вкладка создаёт случайный session ID; адреса получают префикс /app/<session>/. По нему service worker находит вкладку-владельца, её shell.js передаёт запрос в отдельный web worker, а тот вызывает Datasette через ASGI и SQLite. Статус, заголовки и тело ответа возвращаются той же цепочкой к iframe.

Python остаётся в отдельном web worker ещё и потому, что браузер может прекратить жизнь service worker примерно через тридцать секунд; хранить там долгоживущее состояние приложения ненадёжно. Схему этого обмена Уиллисон попросил Fable 5.2 изобразить в SVG и включил один из вариантов в README.

Datasette должна работать с SQLite начиная с 3.25, выпущенной в сентябре 2018 года. В статье Уиллисон рассказывает о сборке WebAssembly wheel-файлов pysqlite3 для 163 версий SQLite. Параметр sqlite= выбирает нужный пакет, устанавливает его в Pyodide и подключает к Datasette.

Так можно открыть точную версию движка, проверить странность и закрыть вкладку, не перестраивая локальный Python на Mac. Из этой работы вырос отдельный инструмент сравнения SQL: он показывает, как один запрос возвращает JSON-объект, где значение поля a в SQLite 3.54.0 оказывается массивом, а в 3.54.1 — строкой с тем же представлением массива.

Эта схема началась в мае как исследовательский spike, созданный с помощью Claude Opus 4.8. До ноября и Fable 5.2 Уиллисон не чувствовал, что понимает её достаточно хорошо для production. В статье он уже использует её в обычной разработке и обсуждении ошибок.

Он видит тот же способ у большинства Python-приложений: браузерные preview-окружения, демонстрации и воспроизведение сбоев. Кодовые агенты помогают компилировать C- и Rust-расширения под Pyodide-совместимый WebAssembly; такие wheel-файлы уже можно публиковать в PyPI. SQLite подходит естественно, а путь с PostgreSQL или MySQL пока менее отработан.
