GitHub × Кайл Дейгл: разработка агентами меняет инфраструктуру и правила доверия

Три основных вывода

  1. Агентный поток изменил профиль нагрузки. Дейгл сравнивает один миллиард коммитов за весь 2025 год с 275 миллионами за неделю весной 2026-го. Увеличилось не только число пользователей: агенты создают больше и крупнее PR, нагрузку на Actions и большие репозитории. Поэтому обычное добавление серверов уже не решает всё; GitHub пересматривает очереди, права доступа и старые базы, включая центральный слой разрешений MySQL One. [47:38–56:22]
  2. Рост PR обнажает вопрос доверия, который нельзя решить одной проверкой синтаксиса. При коде от агента, обзоре другим агентом и финальном взгляде человека непонятно, чей авторитет подтверждает изменение. Дейгл обсуждает vouching мейнтейнеров, спонсорство как затратный сигнал и правила допуска, настраиваемые самим проектом; звёзды и возраст аккаунта легко накручивать, а единое правило GitHub не подойдёт всем сообществам. [33:13–40:47]
  3. Copilot меняет устройство после того, как общий прогресс моделей опередил ставку GitHub на тонкую настройку автодополнения. Общая SDK и агентная обвязка теперь работают в CLI, настольном приложении и облачных агентах; тот же контур можно послать на issue, исправление уязвимости или сверку документации с репозиторием. Следующий дефицит, по Дейглу, — контекст переписки, спецификаций и решений других команд, которого одному коду недостаточно. [1:02:04–1:11:42]

Оригинал

Кто говорит: Кайл Дейгл — операционный директор GitHub и CMO направления для разработчиков Microsoft; беседует с ведущим Latent Space Шоном Ваном.

Главная мысль: Когда код и запросы на его проверку массово создают агенты, GitHub приходится перестраивать не только вычислительную инфраструктуру, но и социальный механизм доверия к изменениям. Компания одновременно превращает Copilot из автодополнения в рабочую среду для агентов, связанных с контекстом всей организации.

  • Агентный поток изменил профиль нагрузки. Дейгл сравнивает один миллиард коммитов за весь 2025 год с 275 миллионами за неделю весной 2026-го.   • GitHub Actions фактически стал слоем вычислений для CI, автоматизаций и агентных задач. Новым сборкам нужны CPU и быстро запускаемые изолированные среды. Дейгл связывает развитие этого слоя с прежним переходом от исполнения произвольного Ruby-кода для интеграций к контейнеризации и с расширением мощностей в Azure. [22:15–26:07; 51:18–53:17; 59:21–1:00:41]
  • Ведущий предлагает, чтобы агент копировал из открытого проекта лишь нужный исходный код вместо подключения большого npm-пакета. Дейгл видит пользу в меньшей поверхности зависимостей: такой выбор делали и до AI. Но это не снимает проблему безопасности — агента тоже можно убедить принять вредоносный код. Поэтому статический анализ, проверки во время исполнения и правила допуска остаются нужны независимо от того, берут целый пакет или один файл. [28:43–31:35]

[33:13–40:47]
  • Во внутренней работе GitHub раздаёт сотрудникам CLI, доступ к GitHub, Teams, Slack и почте через Work IQ и небольшие общие навыки. Дейгл сначала поручает агенту собрать, что произошло за неделю в PR, документах и разговорах, а затем предлагает изменения на ближайшие дни. Узкие навыки легче исправлять и сочетать, чем большой сценарий, который пытается сразу сделать весь отчёт. [3:40–14:37]

Одновременно GitHub сохраняет код видимым даже в простом конструкторе Spark: новичок может запустить приложение, а затем перейти к исправлению кода и более сложной разработке.
