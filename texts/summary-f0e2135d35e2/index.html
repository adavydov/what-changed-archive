GitHub: агенты меняют нагрузку, доверие и саму единицу работы

COO GitHub и руководитель developer marketing Microsoft Кайл Дейгл беседует со swyx о внутренних AI-процессах, сбоях GitHub и следующем этапе Copilot. Разговор идёт от повседневной работы руководителя к архитектуре платформы и социальным правилам open source.

Основные мысли

  • GitHub внедряет небольшие навыки поверх привычных каналов работы и использует агентов для восстановления контекста компании.
  • Агенты увеличили размер операций и число запусков: обычного добавления серверов оказалось недостаточно.
  • Проверка кода и доверие к участнику — разные задачи; GitHub ищет гибкие инструменты репутации и контроля.

AI возвращает руководителя к созданию инструментов

Дейгл снова активно пишет код, соединяя накопленный опыт управления с возможностью быстро собирать приложения. Его типичная задача начинается с ретроспективы: агент просматривает pull requests, публичные сообщения, заметки Obsidian, расшифровки Teams и Slack, затем объясняет, что произошло за неделю и что стоит поправить в ближайшие несколько дней. Для распределённой компании это возвращает информацию, которую человек неизбежно пропускает.

GitHub старается внедрять такие возможности поверх существующей работы. Компания сохраняет Slack для ChatOps и Teams для видеовстреч: перенос множества встроенных команд был бы дорогим. Сотрудникам, включая нетехнических, дают CLI, доступ к корпоративному контексту и навыкам; результаты автоматических запусков возвращаются в issues и discussions. Инструмент помогает продолжать привычный разговор.

Маленькие навыки вместо больших инструкций

GitHub уходит от огромных skills, описывающих весь процесс, к маленьким повторно используемым действиям. Большая инструкция хрупка: через несколько месяцев меняются источники, требования и последовательность шагов, а поправить одну часть становится сложно. Маленький навык может, например, выделять маркетингово значимую информацию из любого MCP-источника.

При этом хорошее summary для аналитика Gartner, клиента и PR-команды имеет разный смысл. Дейгл разделяет техническую операцию и профессиональные критерии результата: атомарная способность соединяется с тем, что важно конкретной роли. Сотрудник может открыть текст навыка и изменить его обычным языком. Именно эти небольшие различия часто определяют, воспринимается ли результат как полезный рабочий документ.

Что остаётся человеку

Для годового планирования Дейгл собрал информацию, сделал небольшое приложение для просмотра SQLite и подготовил презентацию для CRO, CFO и их команд. Он намеренно попросил не делать её эффектной: цель была передать информацию в привычном виде. На встрече вопрос об AI-происхождении не возник.

Работа chief of staff при этом сохраняется. В ней становится меньше изготовления слайдов и больше поиска человеческих связей: с какой командой руководителю нужно встретиться, где есть возможность, как использовать поездку в другой город. Дейгл видит особенно сильный эффект у людей, которые соединяют опыт разработки с другой предметной областью: они умеют сформулировать проблему и теперь способны сами создать средство её решения.

Почему GitHub столкнулся с новым видом масштабирования

В разговоре обсуждаются 1 млрд commits за 2025 год и 275 млн в неделю весной 2026-го — темп, который при линейном продолжении дал бы около 14 млрд за год. Дейгл говорит, что рост продолжает ускоряться. Меняется не только количество пользователей, но и размер самой операции: push и pull request содержат больше изменений, крупные monorepo встречаются чаще, каждый агент запускает новые сборки.

Больше сборок означает потребность в CPU, а не только GPU. GitHub расширяет вычисления в Azure и дополнительных облаках. Другой узкий участок — права доступа: многие permissioning-запросы всё ещё сходятся в историческую базу MySQL One. Вынос сервисов и шардирование через Vitess помогают, но новые комбинации нагрузки требуют переработки архитектуры. Параллельно GitHub должен поддерживать Enterprise Server на инфраструктуре клиента и режимы резидентности данных.

Исторические способы масштабирования — больше серверов или более мощная база — не закрывают все проблемы при дефиците вычислений и изменившемся характере работы. Команда переписывает очереди, ускоряет Git для больших репозиториев и пересматривает неудачные решения в PR-интерфейсе. Дейгл ожидает заметного снижения числа инцидентов в следующие три месяца по мере завершения крупных изменений и обещает подробнее объяснять техническую работу публично.

Безопасное выполнение и зависимости

GitHub Actions вырос из ранних систем, которые исполняли пользовательский код от имени интеграций. Теперь нужны изоляция, контейнеризация и быстро запускаемые небольшие вычислительные окружения для агентов. Actions фактически стал общим вычислительным слоем: его используют для CI/CD, автоматизации и обработки данных. Поэтому нагрузку нельзя понять только через число тестовых сборок.

История npm показывает другую границу: ужесточение 2FA, смена токенов и отзыв обнаруженных секретов повышают безопасность, но могут ломать давно работающие цепочки пользователей. Дейгл считает, что переход к копированию небольших фрагментов зависимостей агентом не решит проблему автоматически. Агент тоже может ошибиться или поддаться манипуляции; статический анализ и проверка исполнения остаются нужны. Уменьшение объёма импортируемого кода меняет масштаб проверки, а не отменяет её.

Доверие нельзя свести к ещё одному AI-review

Когда код написал агент, проверил другой агент, а человек просмотрел результат, доверие становится рассеянным. Больше проверочных материалов помогает оценить изменение, но не отвечает полностью на вопрос, можно ли доверять отправителю. Поэтому идеи prompt requests, vouching и передачи всех исходных артефактов решения полезны, однако единого стандарта пока нет.

GitHub предпочитает давать сопровождающим гибкие средства и закреплять практику после её принятия сообществом. Универсальные пороги легко атаковать: если важен возраст аккаунта, злоумышленник заранее создаёт аккаунты; если количество PR — участники обмениваются фиктивными изменениями. Репозиторий может использовать собственную комбинацию истории принятых PR, внешних социальных сигналов и других условий. Дейгл отдельно выделяет Sponsors: финансовая поддержка требует затрат и потому отличается от бесплатной звезды.

Рост звёзд всё же нельзя целиком объяснить ботами. На GitHub уже больше 200 млн пользователей, которых компания относит к разработчикам, включая людей, начавших создавать приложения с AI. Их интерес быстрее переключается между новыми инструментами. GitHub старается принимать эту аудиторию без отдельной платформы и даже в Spark не скрывает код: доступ к реализации помогает человеку постепенно осваивать разработку.

Почему Copilot перестраивается вокруг общего harness

После успеха автодополнения команда Copilot вложилась в fine-tuning, в том числе под отдельных клиентов. Улучшение базовых моделей изменило траекторию рынка быстрее, чем ожидалось. Теперь CLI, desktop app и cloud agents используют общий SDK и harness. Дейгл описывает более широкую область автоматизации: устранение уязвимостей, разбор каждого нового issue, поиск расхождений документации и реализации.

Следующая сложность — чтобы агент действовал с учётом предпочтений человека и команды, не требуя каждый раз заново описывать их правила. Для этого одного кода недостаточно: решения зависят от спецификаций, писем, разговоров и бизнес-ситуации. Дейгл видит потенциал ambient AI, который соединяет такие источники и проактивно предлагает работу. Это пока направление развития; нынешние инструменты в основном захватывают информацию и затем её извлекают.

Корпоративному агенту нужны компоненты платформы

Интерес Microsoft к OpenClaw Дейгл связывает с доступом агента к ресурсам пользователя и умением действовать на компьютере. На рабочем устройстве для этого нужны другие средства изоляции, права и контроль на уровне ОС. Компания инвестирует в платформенные компоненты, чтобы разработчики могли собирать собственные варианты, а не повторять одну вертикальную оболочку.

В финале Дейгл возвращается к WorkIQ и FoundryIQ: они должны позволять спрашивать о существующих корпоративных данных без миграции на новые инструменты и в пределах привычных ограничений безопасности. Он формулирует цель как возможность строить на работе с той же скоростью, что и в личном проекте. Команды контекста и Copilot уже сближаются: различие между кодом и остальными рабочими материалами сохраняет технические особенности, но общий агент нуждается в них вместе.
