Matt Garman: облако для агентов и новая организация работы AWS

Три основных вывода

  1. Агенты чувствительны к редким задержкам и хотят запускать базы за секунды для коротких задач. AWS Context в предварительном доступе связывает S3, Aurora и другие хранилища для поиска агентом. Упрощённая регистрация с настройками по умолчанию даёт полноценный аккаунт без будущей миграции; её развёртывание продолжается.
  2. Полномочия агента ограничивают сроком и конкретными действиями. MicroVM Firecracker быстро создают изолированные среды с малым накладным расходом. Для временной базы AWS ищет сочетание быстрого старта и возможности сохранить её производственной: заранее неизвестно, какой эксперимент станет постоянным сервисом.
  3. Внутри Amazon функциональные сотрудники строят агентов для HR и налоговых задач, снимая зависимость от очереди разработчиков. Continuum выводит наружу собственные методы AI-безопасности AWS: находит уязвимости и ранжирует их с учётом прав и компенсирующих мер. В разработке компания испытывает группы из трёх-четырёх человек вместо десяти: они быстрее создают продукт и переходят к следующей проблеме. Открытый организационный вопрос — кто затем поддерживает уже созданные системы.

Оригинал

Кто говорит: Мэтт Гарман, CEO Amazon Web Services и первый руководитель EC2; интервью a16z.

Главная мысль: Агентам нужны быстро создаваемые ресурсы, точные временные права и доступный контекст. AWS перестраивает облачный вход, инфраструктуру и команды вокруг этих требований, одновременно расширяя физическую вычислительную мощность.

  • Агенты чувствительны к редким задержкам и хотят запускать базы за секунды для коротких задач. AWS Context в предварительном доступе связывает S3, Aurora и другие хранилища для поиска агентом. Упрощённая регистрация с настройками по умолчанию даёт полноценный аккаунт без будущей миграции; её развёртывание продолжается.
  • Полномочия агента ограничивают сроком и конкретными действиями. MicroVM Firecracker быстро создают изолированные среды с малым накладным расходом. Для временной базы AWS ищет сочетание быстрого старта и возможности сохранить её производственной: заранее неизвестно, какой эксперимент станет постоянным сервисом.
  • Агент позволяет заново определить способ достижения результата — например, параллельно попробовать 50 вариантов вместо пяти последовательных шагов сотрудника. Компании нуждаются в размеченных данных, оценочных сценариях, мониторинге и проверке отклонений. AWS хочет примерно за 45 дней научить заказчика самостоятельно поддерживать этот цикл через совместную работу выездных инженеров.
  • По Гарману, Bedrock удерживает запросы в доверенной среде клиента, не передавая поставщику модели. Дообучение и сжатие открытых моделей на собственных данных может улучшить качество и цену специализированной работы. SageMaker уже обслуживает такое обучение и исполнение; выигрыш проверяют собственными оценочными сценариями.
  • Дефицит GPU AWS распределяет сознательно: часть мощности сохраняет для стартапов, хотя её могли бы выкупить крупнейшие лаборатории. Гарман приводит план закупки двух миллионов Nvidia GPU за несколько лет и инвестиционные расходы $220 млрд за 2026 год. Ограничение постоянно перемещается между электричеством, памятью, чипами, сетью и строительством. Ссылаясь на книгу «Цель», он объясняет, почему нельзя решить один дефицит и считать задачу законченной; энергопроекты требуют планирования на десятилетия.
  • Собственные чипы выросли из конкретной системной проблемы. Nitro вынес виртуализацию сети и хранения на отдельную карту, улучшив производительность и изоляцию; ARM-компоненты затем привели к Graviton. Trainium оказался важен и для исполнения больших моделей, на нём работает большая часть нагрузки Bedrock. Гарман связывает эту линию с ценой и производительностью всей системы, а не только отдельного ускорителя.
  • Внутри Amazon функциональные сотрудники строят агентов для HR и налоговых задач, снимая зависимость от очереди разработчиков.
