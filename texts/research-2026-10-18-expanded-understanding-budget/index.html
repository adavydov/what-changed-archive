После генерации остаётся цена понимания

Исследовательская гипотеза

Саймон Уиллисон поручил Claude Code сделать SPARQL внутри SQLite на Rust. Система строила сеть подагентов и работала больше 12 часов; на следующий день он уже просил README для каждого crate, учебник и демонстрационную базу. Автор прямо признаёт: код практически невозможно обозреть целиком, даже чтение документации требует существенного вложения времени, а реальная полезность созданного на пробу продукта ему пока не ясна.

Это отдельный предел, который не сводится к числу багов. Можно получить объёмную реализацию и тесты, но не получить человека, который понимает, что с ней делать, какие возможности нужны и где заканчиваются гарантии. Эксперимент не доказывает неработоспособность проекта; он показывает, что выпуск кода и освоение результата требуют разных бюджетов.

Связь с Cognition здесь предметная: когда исполнение ускоряется, выбор нужной работы и способность принять её становятся частью себестоимости полезного исхода. Связь с Claude Code другая: там для конкретного модуля заказывают объяснение и обсуждают изменения, отделяя распространение понимания от поиска ошибок. Универсального доказанного решения этой новой очереди работ источники не дают.

Редакторская гипотеза. Сопоставление трёх источников — редакторская интерпретация: проверка ошибок, понимание системы и выбор нужной работы представляют разные затраты на принятие результата.

Один авторский эксперимент и сопоставление разных отраслевых процессов; общий размер затрат не измерен.

Следующее свидетельство: Время до понимания и полезного применения разных автономно созданных систем.
