Короткий человеческий вход в длинное описание работы агента

Саймон Уиллисон использует pull request как единицу работы: собирает в нём коммиты, решения и проверки, пока функция не готова к слиянию. В этой статье он объясняет, как оформляет подробные описания, написанные Claude Code и Codex, чтобы читатель мог быстро решить, чему уделить внимание.

По наблюдению Уиллисона, нынешние агенты хорошо описывают задачу, решение и способы проверки. Проблемой становится объём: даже точный текст выглядит как поток, на чтение которого уйдёт больше времени, чем человек потратил на его создание. Автор замечает эту реакцию и на собственные PR, подготовленные агентом.

Ему нужен человеческий редакторский вход: кто-то должен немного подумать о работе и объяснить на высоком уровне, зачем она нужна и стоит ли изучать детали. Это обещание читателю, что самое короткое введение уже прошло содержательный отбор.

В начале PR Уиллисон оставляет короткий абзац с объяснением изменения, иногда дополняя его снимком экрана. Полное описание агента помещается в HTML-блок <details><summary>, поддерживаемый GitHub Markdown. В заголовке раскрывающегося блока он указывает модель и нередко уровень усилия, например Claude Opus 5.5 Medium. Подробности остаются доступны одним нажатием.

Вступление необязательно писать с нуля. Иногда нужная фраза уже есть среди длинного ответа агента: задача человека — выбрать её. В одном PR достаточно было объяснить, что строка таблицы из 46 колонок уходила далеко вправо и теперь показывается вертикальным списком полей; в другом — что файл edit-tools.js размером около 220 КБ загружался даже пользователям без права редактирования и теперь подгружается при первом взаимодействии с редактированием. Другие примеры автора показывают верхнюю навигацию по страницам, новый механизм расширения тегов чата и команды управления совместимыми с OpenAI endpoints.

Чтобы помнить порядок тегов, Уиллисон предлагает произносить details-summary: сначала контейнер подробностей, затем его краткий заголовок. Слово summary обозначает строку, на которую нажимают для раскрытия. В финале он желает GitHub добавить эту возможность кнопкой в редактор — это сократило бы ручной ввод, особенно с телефона, и сделало приём заметнее для других пользователей.
